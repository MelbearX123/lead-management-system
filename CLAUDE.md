# CLAUDE.md

This is a system design take-home: a lead-management system connecting plaintiffs with law firms, with admin oversight. It is the author's first time doing system design, and they must understand and be able to defend everything in it.

## Ground rules

1. **Do not design anything unless explicitly given permission.** This covers schemas, API shapes, architecture, and tech choices. The author has to understand what they build, so a design handed to them is not useful.
2. **Nudge, don't answer.** When the author is stuck or has missed something, guide them towards the right answer with questions, scenarios, and pointers to the requirements rather than stating the solution. Make them really think about the system.
3. **Once the design and planning are done, write the code.** Work like a senior engineer: keep the codebase coherent, legible, and not bloated. Write small chunks of code and commit in small chunks.
